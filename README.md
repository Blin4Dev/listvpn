# listvpn

Сеть VPN-сервисов на одном бэкенде: **BatmanVPN**, **FGN** и следующие проекты.
Одна база, одна панель (переключатель «Проект»), общий Remnawave; у каждого проекта свои
бот, канал, мини-приложение (дизайн), платёжка ЮKassa, цены и пользователи.
Как устроено и как добавить проект — [projects/README.md](projects/README.md).

## API v1

Клиентский API: `/api/v1/subscription`, `/subscription/resync`, `/tariffs`, `/referrals/me`,
`/referrals/withdrawals`, `/tasks`, `/tasks/{id}/claim`, `/telemetry/sessions` и вебхук ЮKassa
`/webhooks/payments/yookassa`. Для разработчика клиента — [docs/API_V1_CLIENT.md](docs/API_V1_CLIENT.md), устройство на сервере — [docs/API_V1.md](docs/API_V1.md).
Отдельный домен API без префикса: `API_DOMAIN=api.example.com` в `.env` → `install.sh` → 1.
После обновления (`install.sh` → 1) таблицы создаются сами; в кабинете ЮKassa можно указать
`https://<домен>/webhooks/payments/yookassa` (старый `/yookassa` тоже работает).

## Панель на отдельном сервере

При установке `install.sh` спрашивает «Установить панель на ОТДЕЛЬНЫЙ сервер?». Для уже установленного бота: `install.sh` → «Перенести панель на отдельный сервер».

Что нужно: сервер Debian/Ubuntu, A-запись домена панели на него, SSH под root (или пользователем с `sudo` без пароля).

Как работает:
- установщик один раз входит по паролю, добавляет отдельный ключ (`~/.ssh/blinvpn_panel_ed25519`, вход только с IP сервера бота) и дальше работает по ключу; пароль не сохраняется; отпечаток SSH-сервера подтверждается вручную;
- на сервере панели: Caddy (сам выпускает и продлевает сертификат), статика в `/var/www/blinvpn-panel` (атомарная смена версий, хранятся 3 последние);
- `/api/panel` сервер панели проксирует на сервер бота по HTTPS с проверкой сертификата и секретным заголовком; на сервере бота `/api/panel` открыт только для IP сервера панели и только с этим заголовком;
- настройки и секрет шлюза — в `.env.panel-remote` (права 600, в контейнеры не попадает);
- обновление бота (`install.sh` → 1) обновляет и панель на отдельном сервере.


## Caddy вместо nginx

Внешний прокси — Caddy: сам выпускает и продлевает сертификаты Let's Encrypt, certbot не нужен.
Конфиги: `/etc/caddy/Caddyfile` (глобальные опции, управляется установщиком) и `/etc/caddy/sites/*.caddy`
(BatmanVPN — `blinvpn.caddy`; свои сайты кладите туда же отдельными файлами).
Установка на nginx-версии переезжает автоматически при обновлении (`install.sh` → 1): если Caddy не получит
сертификат, nginx возвращается как был. Контейнеры мини-приложения и панели тоже на Caddy (`docker/Caddyfile.spa`).

## Caddy уже есть на сервере (Remnawave и т.п.)

Если порты 80/443 держит Caddy в Docker-контейнере (`network_mode: host`, например `/opt/remnawave/caddy`),
установщик предложит подключиться к нему: свой Caddy не ставится, сайты listvpn пишутся отдельным файлом
`blinvpn.caddy` в папку сайтов этого контейнера (та, что подключена через `import …/*.caddy` и смонтирована с хоста),
затем `caddy validate` и `caddy reload` внутри контейнера; при ошибке файл откатывается, чужие сайты не трогаются.
Выбор сохраняется в `.env` (`CADDY_CONTAINER`, `CADDY_SITES_DIR`). Чтобы мини-приложения проектов можно было ставить
на сервер панели, в Caddyfile контейнера добавляется глобальный `on_demand_tls { ask … }` (если файл смонтирован с хоста).

## Порт HTTPS

При установке спрашивается порт (Enter = 443). Для готовой установки: `install.sh` → «Сменить порт HTTPS».
С портом не 443 адреса будут вида `https://домен:порт` (мини-приложение, панель, API), а порт 443 остаётся свободным (например, под Xray).
Порт 80 при этом всё равно нужен — через него Caddy получает сертификат. ЮKassa присылает уведомления только на 443/8443,
Telegram webhook — только на 443/80/88/8443, поэтому, если 443 занят, лучше выбрать 8443. Сервер панели работает на том же порту.

## Сервер панели: свой прокси

При установке панели на отдельный сервер установщик спрашивает «На сервере панели настроить Caddy и сертификат автоматически?».
Если там уже есть свой прокси (например, Remnawave занимает порты 80/443) — ответьте `n`: установщик выложит только файлы панели
в `/var/www/blinvpn-panel/current/html` и даст инструкцию с примерами для Caddy и nginx (`/var/www/blinvpn-panel/proxy/`).
Поменять выбор: `install.sh` → пункт 3. На сервере бота Caddy всегда настраивается автоматически.


## Домены ссылок подписки

В `.env`: `VPN_SUB_DOMAIN` — домен ссылок подписки VPN.
Бот берёт ссылку из Remnawave и меняет в ней только домен: `https://domain1.com/hIeb` + `VPN_SUB_DOMAIN=domain2.com` → `https://domain2.com/hIeb`.
Пусто — ссылка без изменений. Действует сразу для всех ссылок, в том числе уже выданных (после `docker compose up -d`).


## Порт вебхука

`WEBHOOK_PORT` в `.env` (по умолчанию `5000`) — внутренний порт сервиса вебхуков (уведомления ЮKassa), слушает только `127.0.0.1`.
Снаружи порт не меняется: ЮKassa по-прежнему шлёт на `https://<домен>/yookassa/...`, Caddy проксирует на новый порт.
Сменить: поменяйте `WEBHOOK_PORT` в `.env` → `install.sh` → пункт 1 (контейнеры и Caddy перезапустятся с новым портом).
Порт: 1024–65535, не занятый другой программой и не совпадающий с портами BatmanVPN (80, 3000, 8000, 9741, 9742, порт HTTPS).


## Домен вебхуков

Уведомления ЮKassa (`/yookassa`) и Telegram (`/api/telegram/webhook`) можно принимать на отдельном домене (`WEBHOOK_DOMAIN` в `.env`).
Установщик спрашивает его при установке (Enter — тот же, что у мини-приложения); сменить — `install.sh` → пункт 2 «Заменить домены».
На отдельном домене Caddy выпускает свой сертификат и отдаёт только эти два адреса, всё остальное — 404.
Адрес на домене мини-приложения (`https://<домен мини-приложения>/yookassa`) тоже продолжает работать.
A-запись домена вебхуков должна указывать на сервер бота.
