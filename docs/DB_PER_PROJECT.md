# База у каждого бота своя

```
data/
  core.db              общее: панель, сотрудники, настройки, тарифы-планы, серверы, мониторинг
  projects/fgn.db      всё FGN: пользователи, подписки, платежи, поддержка, промокоды, рефералка…
  projects/batman.db
  projects/hustler.db
  projects/ovpn.db
  projects/lyam200.db
  projects/rvpn.db
  db-split.json        отметка о переносе (когда, сколько строк, где копия)
  data.db.pre-split    старая общая база (не используется, лежит на всякий случай)
  backups/pre-split-*.db  копия старой базы, снятая прямо перед переносом
```

## Перенос

Происходит сам, один раз, при первом запуске после обновления (`install.sh` → «1) Обновить код»).

1. Снимок старой `data.db`, на время снимка запись в базу ждёт. Копия снимка — в `backups/pre-split-<время>.db`.
2. Строки раскладываются по проектам: по `project_id`, а у строк без него — по владельцу
   (платёж → пользователь, сообщение поддержки → переписка → пользователь и т. д.).
3. Сверка: каждая таблица построчно (количество + контрольная сумма содержимого) против старой базы, проверка целостности
   каждого файла. Любое расхождение — перенос отменяется, работа продолжается на старой `data.db` как раньше,
   причина пишется в `data/db-split.failed`.
4. Только после успешной сверки: новые файлы на место, `data.db` → `data.db.pre-split`.

В логе сервиса `api`:

```
[db] перенос по проектам: копия старой базы — backups/pre-split-….db
[db] перенос по проектам: проекты fgn, batman, hustler, ovpn, lyam200, rvpn
[db] перенос по проектам: готово, таблиц 75, строк …, всё совпало
```

## Что не меняется

* Номера записей старых пользователей, подписок, платежей — те же.
* Новые номера у каждого проекта из своего диапазона (FGN — от 1 000 000 001, следующий — от 2 000 000 001 …),
  поэтому номер записи по-прежнему однозначен во всей сети.
* Промокоды, коды ссылок, реф. коды по-прежнему уникальны во всей сети.
* Панель («вся сеть» и по проекту), бот, мини-приложения, сайты, оплата, фоновые задачи — работают как раньше:
  код остался тот же, раскладку по файлам делает `src/core/dbshard.py`.
* Бэкап из панели — по-прежнему один файл прежнего формата (собирается из всех баз).

## Команды

```bash
# состояние: режим, проекты, сколько пользователей/подписок в каждом файле
docker compose exec api python /app/src/core/dbshard.py status

# вернуть одну базу (сервисы остановлены): соберёт data/data.db, файлы по проектам уберёт в data/split-<время>/
docker compose run --rm api python /app/src/core/dbshard.py merge-back
# затем в .env: DB_SPLIT=0 и перезапуск
```

`DB_SPLIT=0` в `.env` — не делить базу (остаться на одной `data.db`). Если база уже поделена, сервис с `DB_SPLIT=0`
не запустится, пока не сделан `merge-back` (чтобы не работать со старой копией).

Повторить неудавшийся перенос: удалить `data/db-split.failed` и перезапустить.
