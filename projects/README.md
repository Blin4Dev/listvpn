# Проекты сети listvpn

listvpn — сеть VPN-сервисов на **одном** бэкенде, одной базе и одной панели.
Каждый проект (BatmanVPN, FGN, …) — отдельный бренд со своим:

| Своё у проекта | Где задаётся |
|---|---|
| Название, канал, тексты бота, фичи | `projects/<id>/project.json` |
| Дизайн мини-приложения, эксклюзивные экраны | `projects/<id>/app/` (переопределения файлов `src/app/`) |
| Картинки, видео, иконки | `projects/<id>/assets/` (поверх общих `assets/`) |
| Бот, канал, магазин ЮKassa, домены подписки | панель → Настройки → «Проект: бот и оплата» (в базе, секреты зашифрованы) |
| Домен мини-приложения | `install.sh` → «Проекты сети» (нужен сертификат) |
| Цены, тарифы, пробный период, промокоды, акции, ссылки, рассылки, юр. документы | панель → переключатель «Проект» |
| Пользователи | у каждого проекта свои аккаунты: один человек в BatmanVPN и FGN — два разных аккаунта |

Админы сети (кому приходят коды входа в панель) и форум уведомлений — панель → Настройки → Уведомления.

Общее для всей сети: Remnawave (сквады, ноды), сотрудники и поддержка (одна команда,
чаты всех проектов с пометкой проекта), мониторинг, балансировщик, анти-абуз, почта, бэкапы,
чёрный список. Служебные сообщения команде (форум, коды входа в панель) отправляет бот основного проекта.

## Основной проект

`batman` (BatmanVPN) — основной: его домен — `MINIAPP_DOMAIN` в `.env`. Сменить основной — `DEFAULT_PROJECT=` в `.env`.
Бот / ЮKassa, оставшиеся в `.env` от старой установки, продолжают работать; сохранённое в панели важнее.

## Добавить проект

1. `sudo bash install.sh` → «Проекты сети» → новый id (например, `fgn2`) и домен.
   Установщик скопирует основной проект в `projects/fgn2/`, пересоберёт контейнеры и выпустит сертификат.
   Больше он ничего не спрашивает.
2. Панель → переключатель «Проект» → новый проект → Настройки → «Проект: бот и оплата»:
   токен бота (бот подключится сам за ~10 секунд, без перезапуска), канал, ЮKassa.
3. В @BotFather — Web App URL проекта; в ЮKassa — уведомления на адрес, который показан в панели.

Вручную вместо шага 1: `cp -r projects/batman projects/<id>`, поправить `project.json`
(`id` = имя папки, `name`), в `.env` — `<ID>__MINIAPP_DOMAIN=…` и `<ID>__MINIAPP_URL=https://…`, затем `install.sh` → 1.

Новый проект при первом запуске получает **копию** цен, тарифов и документов основного проекта
(в документах название заменяется на название проекта) — дальше они меняются независимо.

## Дизайн и эксклюзивные фишки

Мини-приложение одно (`src/app/`), проект собирается командой `PROJECT=<id>` (все — `npm run build:miniapp`).
Чтобы изменить что-то только у одного проекта, положите файл с тем же путём в `projects/<id>/app/`:

    src/app/components/noir.tsx  →  projects/fgn/app/components/noir.tsx   (палитра, кнопки)
    src/app/pages/Home.tsx       →  projects/fgn/app/pages/Home.tsx        (свой главный экран)

Импорты внутри такого файла пишутся как в оригинале (`../utils/api`). Флаги фич — `features` в `project.json`
(на бэкенде: `projects.current().feature("имя")`).

## Как бэкенд понимает проект

- мини-приложение шлёт `X-Project: <id>` (вшит при сборке), Caddy на домене проекта ставит его же;
- initData проверяется токеном бота **этого** проекта; сессия другого проекта не принимается;
- панель шлёт `X-Project` выбранного проекта; действия над конкретной записью (пользователь, платёж,
  чат…) выполняются от имени её проекта — сообщение пользователю FGN уйдёт ботом FGN;
- вебхук ЮKassa находит платёж и проверяет его ключами магазина его проекта;
- фоновые задачи (напоминания, анти-абуз, рассылки) идут по проектам, каждый — своим ботом.

API v1 (`/api/v1`): для не-основного проекта клиент передаёт `X-Project: <id>`.
Telegram webhook (режим `TELEGRAM_STARS_DELIVERY=webhook`): `https://<домен>/api/telegram/webhook/<id>`.
